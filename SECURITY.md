# Security reports

Use this repository's GitHub **Security → Advisories → Report a vulnerability** route if private vulnerability reporting is enabled. Do not put sensitive exploit details, private images, review ZIPs, logs containing personal information, credentials or signing material in public issues.

If the private reporting button is unavailable, open a minimal public issue asking maintainers to enable private reporting. Include no exploit details or personal data. No personal email address or alternative private upload endpoint is configured here.

This beta has no promised response time or long-term support window. Reports should identify the version, affected feature, impact and a synthetic reproduction where possible. Signing keys and release credentials must remain outside the repository and public build artifacts.
